`docs/superpowers/specs/2026-10-25-a2a-gateway-framework-design.md`. Each row names the
code that handles the condition and the tests that prove it. Test ids are
`path::test_name`; `test_boundaries` means `tests/integration/test_boundaries.py`, and
`test_attack_matrix` means `tests/security/test_attack_matrix.py`.

Partner faults in `test_boundaries` come from `tests/faults.py`. `FaultInjector` wraps a
real partner app and injects latency, an HTTP status, a stream dropped after N events, a
malformed body, or a closed connection. Faults are keyed by JSON-RPC method or REST path.

## Security attack matrix

`tests/security/test_attack_matrix.py` runs the attacker scenarios in parameterized form,
each through a real entry point:

- **SSRF.** 54 URL payloads go through partner card fetch, `a2agw partners add`, push
  webhook configs, the inbound JWT JWKS, the card-signature JWKS and the control plane's
  partner catalogue (`POST /api/v1/partners`). Payloads that must be
  refused on every tier also run on the `internal` tier. The payloads cover:
  - cloud metadata in every encoding: decimal, hex, octal, IPv4-mapped, NAT64, 6to4,
    IPv4-compatible and Teredo
  - loopback, link-local, RFC 1918, ULA, CGNAT, multicast and `0.0.0.0`
  - userinfo tricks
  - schemes other than http(s)
  - IDN homographs
  - trailing dots
  - DNS rebinding through a stub resolver

  Every TCP connect is recorded below the guarded backend. Two control tests prove that the
  recorder sees an allowed connect.
- **Payloads.** Oversized bodies, too many parts and malformed parts.
- **Call contexts.** Forged hop, path, deadline and budget claims, and forged call-context
  JWS.
- **Cards.** Tampered and unsigned partner cards.
- **Authz.** Bypass paths, `root_path` included.
- **Prompt injection.** Injection text in partner cards.
- **Secrets in logs.** The scenarios run with DEBUG log capture. A secret marker in API
  keys, bearer tokens, OAuth client secrets and access tokens, push tokens and credentials,
  Fernet keys, database passwords, URL passwords and key files must never appear in a
  record, in an error, or in CLI output.
