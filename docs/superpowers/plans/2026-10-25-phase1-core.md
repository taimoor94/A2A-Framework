# A2A Gateway Framework — Phase 1 (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `a2agw` Python package. It makes any agent an A2A server (inbound) and gives any agent a registry of partner agents exposed as tools (outbound). Phase 1 ships adapters for plain callables, LangChain, and LangGraph, plus a three-agent demo and an A2A TCK conformance run.

**Architecture:**
- A framework-agnostic core wraps `a2a-sdk` 1.2.x.
- **Inbound:** an `AgentHost` mounts N agents (cards, JSON-RPC, REST, SQLite task store, auth). It drives each agent through the `InboundAdapter` SPI, using neutral events.
- **Outbound:** `PartnerRegistry`, then `PartnerClient` (resilience, call-context, credentials), then `PartnerTool` specs. Adapters project these into native framework tools.
- **Cross-cutting:** the call-context extension, OTel tracing, the event bus, and the read-only management API.

**Tech Stack:**
- Runtime: Python 3.12 (`uv`; supports ≥ 3.11), `a2a-sdk[http-server,sqlite,telemetry]>=1.2.3,<2`, Starlette + uvicorn, httpx, Pydantic v2, SQLAlchemy async + aiosqlite (via the SDK extra), PyJWT[crypto], PyYAML, Typer, OpenTelemetry SDK.
- Optional extras: `langchain-core>=1.7`, `langgraph>=1.2`.
- Tests: pytest, pytest-asyncio, respx.

**Spec:** `docs/superpowers/specs/2026-10-25-a2a-gateway-framework-design.md`. §§7.1–7.6, 7.9, 7.10 (management API only), 8, 9 Phase 1, and 11a apply.

## Global Constraints

- Package name `a2a-gateway`, import `a2agw`, src layout `src/a2agw/`. License Apache-2.0.
- The core (`a2agw.core`, `serve`, `consult`, `context`, `security`, `ops`) must **never** import langchain or langgraph. Each adapter lives in `a2agw.adapters.<name>` behind an extra.
- Target A2A spec 1.0. Pin `A2A-Version: 1.0` on outbound calls. Inbound enables `enable_v0_3_compat=True`.
- Call-context extension URI: `https://a2agw.dev/ext/call-context/v1`. Default `max_hops=8`.
- Discovery mode threshold: more than 12 partners. Default partner deadline 60 s. Default `wait_seconds` 30.
- Circuit breaker: opens after 5 consecutive failures, half-open after 30 s, 1 probe. Bulkhead: 8 concurrent calls per partner.
- Retries: at most 3 attempts, only for connection-level errors raised before a response. Jittered backoff with base 0.2 s and cap 2 s.
- Inbound limits: request body ≤ 10 MiB, ≤ 64 parts per message.
- Partner text in tool results is capped at 64 KiB and tagged untrusted.
- Secrets never appear in logs, traces, the admin API, or exceptions.
- Every module has tests. Run with `uv run pytest`. Lint with `uv run ruff check`.

## Review Focus

1. **Partner answers with a direct `Message` instead of a `Task`.** The tool result is `state="completed"` with the message text and `task_id=None` (test in Task 12).
2. **Partner card has no JSON-RPC interface (REST only), or only an unsupported binding.** REST is chosen. An unsupported-only card gives `PartnerUnavailable` with a clear reason, not a crash (Task 12).
3. **Inbound message with only file or data parts and no text.** The adapter receives the parts and `InboundContext.text == ""`, with no exception (Task 4).
4. **More concurrent calls to one partner than the bulkhead allows.** Extra calls wait within their deadline, then return `state="unavailable"` with `reason="busy"`. No exception reaches the agent (Task 11).
5. **Partner returns an oversized or non-UTF-8 artifact.** Text is truncated to 64 KiB with a `truncated: true` flag. Bytes parts are summarized as `{media_type, size}`, never inlined (Task 13).

  - `remaining(now: float | None = None) -> float | None`
- Produces the contextvar `current_call: ContextVar[CallContext | None]` and the helper `use_call(cc)`, a context manager.

### Task 8: AdapterExecutor (inbound bridge)

**Files:**
- Create: `src/a2agw/serve/executor.py`.
- Test: `tests/serve/test_executor.py`.

**Interfaces:**
- Consumes: Tasks 2, 3, 6, 7.
- Produces `AdapterExecutor(spec: AgentSpec, index: TaskIndex, bus: EventBus, *, local_max_hops=8, local_max_deadline_s=3600.0)`, which subclasses `a2a.server.agent_execution.AgentExecutor`.

**`execute(ctx, queue)` does the following, in order:**
1. Create the task when `ctx.current_task` is None (`new_task_from_user_message`, then enqueue).
2. Parse the call context from `ctx.message.metadata`. If none is present, call `CallContext.new(spec.id)`. Then `.clamp(...)` and `.check_admit(spec.id, allow_reentry=spec.allow_reentry)`. On `CallContextViolation`, call `updater.reject(message=<reason>)` and return.
3. Set `current_call` (Task 3) to `cc.child(spec.id)` while the adapter runs, so outbound calls inherit it.
4. Build `InboundContext`. `resumed=True` when `ctx.current_task` was already in an `INPUT_REQUIRED` or `AUTH_REQUIRED` state.
5. Map adapter events:
   - `Status` → `update_status(WORKING, message)`
   - `ArtifactChunk` → `add_artifact`
   - `NeedInput` → `requires_input`, then stop
   - `NeedAuth` → `requires_auth`, then stop
   - `Usage` → accumulate into task metadata key `a2agw.usage`
   - `Done` → optional text artifact, then `complete`
   - `Failed` → `failed`
   - If the iterator ends without a terminal event, treat it as `complete`.
   - If the adapter raises, call `failed` with message `"internal error"`. Log the details; never send them to the caller.
6. After every state change, call `index.upsert` and `bus.publish("task.state")`.
7. Wrap the run in `asyncio.Task`, kept in `self._running[task_id]`. `cancel()` cancels it, emits `CANCELED`, and calls the registered `on_cancel(task_id)` hook. The host wires that hook to the outbound cascade (Task 15).

  - `text: str`, `artifacts: list[dict]`, `question: str | None`, `reason: str | None`, `truncated: bool = False`

- Produces `PartnerClient(registry, *, credentials: CredentialProvider | None, handles: OutboundHandleStore | None, bus: EventBus | None, http: httpx.AsyncClient | None, default_deadline_s=60.0)`. Its methods:
  - `async consult(partner_id, message: str, *, files: list[tuple[str, bytes, str]] = (), data: dict | None = None, task_id=None, context_id=None, wait_seconds=30.0, inbound_task_id: str | None = None) -> ToolResult`
  - `async check(partner_id, task_id) -> ToolResult`
  - `async cancel(partner_id, task_id) -> ToolResult`
  - `async wait_any(handles: list[tuple[str, str]], seconds: float) -> list[ToolResult]`
  - `async cancel_for_inbound(inbound_task_id) -> int`

**Rules for `consult`:**
- Look up the partner. Anything not `active` gives `unavailable` with a reason.
- Check the breaker, then acquire a slot from the bulkhead.
- Build the child call context from `current_call.get()` (or `new`). Put it in the message metadata, and add `A2A-Extensions` and `A2A-Version: 1.0` service parameters.
- Generate `context_id` when none is given. Generate `message_id` once and reuse it across retries.
- Effective timeout is `min(wait_seconds, cc.remaining(), default_deadline_s)`.
- Stream when the partner card says `capabilities.streaming`. If the stream breaks, call `subscribe` on the task id; if that fails, poll `get_task` every 1 s until the timeout.
- If an error is ambiguous (a read error after the request was sent), call `list_tasks(context_id=...)` to find the task before giving up. Never re-send the message.
- When the timeout is reached and the task is still WORKING, return `state="working"` with the `task_id`. Do not cancel.
- A direct `Message` response gives `completed` with `task_id=None`.
- Choose the binding from the card. Supported bindings are JSON-RPC and HTTP+JSON. If neither is available, return `unavailable` with `reason="no supported binding"`.
- Record the handle and publish `partner.call` to the bus.
- `cancel_for_inbound` cancels every non-terminal handle linked to the inbound task.
